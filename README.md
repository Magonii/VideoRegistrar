# VideoRegistrar — аналитика посетителей ТЦ

Подсчёт входящих и выходящих, заполняемость с оповещениями, очереди, тепловая карта по часам. Видео не покидает здание: наружу идут только события и координаты.

```
Камеры (RTSP) → worker (YOLO + ByteTrack) → backend (FastAPI + PostgreSQL) → интерфейс (React)
```

| Папка | Что внутри |
|---|---|
| `worker/` | Обработка одной камеры: детекция людей, трекинг, пересечение линий, очереди, точки для тепловой карты |
| `backend/` | API, БД, расчёт заполняемости, правила оповещений, WebSocket, демо-симулятор |
| `frontend/` | Обзор, Трафик, Тепловая карта, Очереди, Оповещения, Камеры (редактор линий и зон), Настройки |

## Быстрый старт (демо без камер)

```powershell
./start-demo.ps1
```

Откройте http://localhost:5173. Демо-режим создаёт два этажа с планами, пять камер и неделю истории, затем генерирует события в реальном времени.

## Запуск в Docker

```bash
docker compose up -d --build        # интерфейс на http://localhost:8080
DEMO=1 docker compose up -d --build # то же, но с демо-данными
```

Переменные: `MALL_TZ` (по умолчанию `Asia/Almaty`), `DB_PASSWORD`, `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (уведомления об оповещениях).

## Подключение реальной камеры

1. **Настройки** → добавьте этажи, загрузите планы, задайте вместимость.
2. **Камеры** → «Добавить камеру» (название, RTSP-адрес, этаж).
3. **Разметка** → нарисуйте линии подсчёта и зоны очередей. Стрелка линии показывает направление «внутрь»; для входа в ТЦ это «этаж = 1 этаж, приходят из = Улица», для эскалатора «на 2 этаж из 1 этажа».
4. Запустите worker (Python 3.10–3.12, нужны torch и ultralytics; на GPU работает в разы быстрее):

```bash
cd worker
pip install -r requirements.txt
python -m worker --camera-id 1 --backend http://localhost:8000 --device 0
# проверка на записи:  python -m worker --camera-id 1 --source test.mp4
```

Правки линий и зон worker подхватывает сам в течение 30 секунд. Снимок с камеры появляется в редакторе через минуту после запуска.

5. Для тепловой карты откройте **Разметка → Привязка к плану**, отметьте 4 одинаковые точки на кадре и на плане.

В Docker worker запускается так: `CAMERA_ID=1 docker compose --profile vision up -d worker` (нужен NVIDIA Container Toolkit). По одному процессу на камеру.

## Как считается заполняемость

Каждая линия описывает переход «откуда → куда» (этаж или улица). Заполняемость этажа — накопленный баланс с начала дня; ТЦ — сумма по этажам. Счётчик обнуляется в полночь по часовому поясу ТЦ. Если накопилась ошибка, на странице «Настройки» можно задать фактическое число людей, и подсчёт продолжится от него.

## Тесты

```bash
cd backend && .venv/Scripts/python -m pytest        # API, заполняемость, алерты
cd worker  && python -m pytest tests                # геометрия линий, очереди (без torch)
cd frontend && npm test                             # гомография
```

Бэкенд проверен и на SQLite (по умолчанию), и на PostgreSQL (`TEST_DATABASE_URL=postgresql+psycopg://...`).

## Что сделано и что нет

- Сделано: счёт на линиях, заполняемость по этажам, алерты по заполняемости и очередям (Telegram), очереди с ожиданием, тепловая карта с проигрыванием по часам, редактор линий, зон и привязки к плану.
- Не сделано: авторизация (по решению заказчика), счёт по отдельным бутикам, сопоставление людей между камерами (Re-ID). Схема данных к нему готова: сохраняются `camera_id` и `track_id` каждой точки.
- Worker не проверялся на реальных видеопотоках: геометрия и анализаторы покрыты тестами, но точность детекции нужно измерить на ваших камерах.
- События от worker приходят по HTTP. Шину (NATS/Redis) стоит добавить, когда камер станет много.
- Агрегаты считаются запросами по сырым событиям; при росте объёма добавьте TimescaleDB или материализованные сводки.
