# Лаборатория: несколько камер → одна территория

Офлайн-эксперимент на датасете WILDTRACK (`data/TestDataset1`: 7 камер, калибровка, разметка первых 200 с).
Цель — оценить, насколько хорошо система сама считает людей на общей территории, строит тепловую карту и ловит заходы/выходы.

## Запуск

Нужен Python 3.10–3.12 с PyTorch (CUDA). Окружение: `lab/.venv` (Python 3.11).

```bash
cd lab
.venv/Scripts/python sync.py                              # синхронизация камер -> data/output/sync.json
.venv/Scripts/python detect.py --seconds 200 --fps 5      # YOLO на 7 камерах, ~10 мин на RTX 4050
.venv/Scripts/python fuse.py --seconds 200 --fps 5 --sigma-near 20 --sigma-slope 0.035
.venv/Scripts/python render.py --start 0 --seconds 60     # видео и графики
```

На Windows для кириллицы в консоли: `set PYTHONIOENCODING=utf-8`.

## Просмотр в веб-интерфейсе

```bash
.venv/Scripts/python export_web.py --seconds 200   # видео камер, мозаика и lab.json -> data/output/web (~5 мин)
```

Страница **«Мультикамера»** (`/lab`) показывает все 7 камер синхронно с рамками, вид сверху с тепловой картой, график числа людей и заходы/выходы. Бэкенд отдаёт папку `data/output/web` по адресу `/api/lab/files` (путь можно сменить переменной `LAB_DIR`).

Чтобы площадка появилась в основной системе (страница «Тепловая карта», раздел «Камеры»), импортируйте её как этаж:

```bash
.venv/Scripts/python import_to_app.py --start "2026-10-30 12:00"   # время начала записи по часам ТЦ
```

Скрипт создаёт этаж «Площадка WILDTRACK (7 камер)» с планом в форме территории и 7 камер, затем загружает позиции людей как точки треков. Повторный запуск заменяет точки, а не дублирует их.

Все камеры склеены в одно видео-мозаику 3840×1080. Так они синхронны по построению, и браузер не упирается в лимит 6 одновременных соединений: с 7 отдельными видео седьмое не грузилось. Каждая плитка на странице вырезает свою камеру из мозаики и рисует поверх рамки. Между кадрами детекции (5 к/с) рамки одного трека интерполируются.

## Как устроено

1. **Синхронизация** (`sync.py`). У каждой камеры свой постоянный сдвиг видео: от +9 до +16 кадров при 60 к/с. Он находится сравнением исправленного кадра видео с кадрами датасета.
2. **Исправление дисторсии.** Видео снято с «бочкой» объектива, а калибровка относится к исправленным кадрам. Каждый кадр исправляется до детекции (`undistort_maps`).
3. **Детекция** (`detect.py`): YOLO11m, imgsz 1280, класс «человек».
4. **Территория** (`fuse.py`): клетки земли, где человека надёжно (не меньше 45 px роста) видят минимум 3 камеры, это 314 м².
5. **Склейка между камерами.** Точка у ног каждой рамки переводится на землю. Ошибка позиции растёт с расстоянием, поэтому у каждой точки своя сигма, и склеиваются точки ближе 2σ. Там, где территорию видят 3+ камеры, человек должен подтверждаться минимум двумя.
6. **Трекинг на земле**: венгерский алгоритм, затем сшивка оборванных треков.
7. **Заходы и выходы**: пересечение границы (3 наблюдения подряд), а также появление или исчезновение трека у самой границы.

## Результат на 200 с (сверка с разметкой датасета)

| Метрика | Значение |
|---|---|
| Людей в территории: в среднем найдено / по разметке | 24,0 / 21,5 |
| Ошибка числа людей в кадре | ±3,3 человека |
| Точность / полнота по позициям (порог 75 см) | 0,70 / 0,78 |
| Ошибка позиции на земле (медиана) | 14 см |
| Заходы / выходы: найдено / по разметке | 279 / 253 против 250 / 263 |
| Совпадение отдельных событий (±2 с, ±2 м) | точность 0,62, полнота 0,64 |

Без исправления дисторсии и синхронизации было: F1 0,44, ошибка числа людей ±47.

## Ограничения

- Улица, а не ТЦ; модель не дообучалась.
- Подписи на видео латиницей, потому что OpenCV не рисует кириллицу.
- Заходы и выходы в толпе ловятся примерно в 2 случаях из 3. Итоговые суммы близки к правде за счёт взаимной компенсации ошибок.
